# Fighter API

Небольшое REST API для работы с данными об истребителях. Проект написан на Python с использованием FastAPI. Данные хранятся в памяти приложения и сбрасываются после его перезапуска.

## Требования

- Python версии 3.10 или новее;
- доступ к терминалу или PowerShell;
- `pip` для установки зависимостей.

## Установка в Linux/macOS

Откройте терминал и перейдите в каталог проекта:

```bash
cd path/to/fighter
```

Создайте и активируйте виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установите зависимости:

```bash
python -m pip install --upgrade pip
python -m pip install fastapi uvicorn
```

## Установка в Windows

Откройте PowerShell и перейдите в каталог проекта:

```powershell
cd path\to\fighter
```

Создайте и активируйте виртуальное окружение:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скриптов, выполните команду от имени текущего пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

После этого снова активируйте окружение и установите зависимости:

```powershell
python -m pip install --upgrade pip
python -m pip install fastapi uvicorn
```

Для командной строки `cmd.exe` активация выполняется так:

```bat
.venv\Scripts\activate.bat
```

## Запуск

Активируйте виртуальное окружение, если оно ещё не активировано, и выполните:

```bash
python -m uvicorn main:app --reload
```

После запуска API будет доступно по адресу <http://127.0.0.1:8000>.

Остановка сервера: `Ctrl+C`.

## Проверка работоспособности

### Проверка состояния приложения

Откройте в браузере:

<http://127.0.0.1:8000/health>

Ожидаемый ответ:

```json
{"status":"OK"}
```

Или выполните в Linux/macOS:

```bash
curl http://127.0.0.1:8000/health
```

В Windows PowerShell используйте:

```powershell
curl.exe http://127.0.0.1:8000/health
```

### Проверка документации API

Откройте интерактивную документацию Swagger:

<http://127.0.0.1:8000/docs>

В Swagger можно выполнить запросы к API и проверить ответы без дополнительных инструментов.

### Проверка основных запросов

Получить список истребителей:

```bash
curl http://127.0.0.1:8000/fighters/
```

Ожидаемый результат содержит две записи с идентификаторами `1` и `2`.

Получить истребитель с идентификатором `1`:

```bash
curl http://127.0.0.1:8000/fighters/1
```

Создать истребитель:

```bash
curl -X POST http://127.0.0.1:8000/fighters/ \
  -H "Content-Type: application/json" \
  -d '{"speed": 350}'
```

В Windows PowerShell:

```powershell
curl.exe -X POST http://127.0.0.1:8000/fighters/ `
  -H "Content-Type: application/json" `
  -d '{"speed":350}'
```

Ожидаемый ответ — созданная запись с полями `id` и `speed`.

Удалить истребитель с идентификатором `3` после выполнения запроса создания:

```bash
curl -X DELETE http://127.0.0.1:8000/fighters/3
```

Если приложение отвечает кодами `200` для `GET` и `POST`, а также возвращает JSON с ожидаемыми полями, оно запущено и основные операции API работают.

> В текущей реализации обновление через `PUT` требует отдельной проверки: обработчик использует обращение к Pydantic-модели как к словарю и может вернуть ошибку `500`. Остальные описанные проверки не зависят от этой операции.

## Доступные маршруты

| Метод | URL | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Проверка состояния приложения |
| `GET` | `/fighters/` | Получить список истребителей |
| `GET` | `/fighters/{fighter_id}` | Получить истребитель по идентификатору |
| `POST` | `/fighters/` | Создать истребитель |
| `PUT` | `/fighters/{fighter_id}` | Обновить скорость истребителя |
| `DELETE` | `/fighters/{fighter_id}` | Удалить истребитель |

Интерактивная документация с описанием схем запросов доступна по адресу <http://127.0.0.1:8000/docs>.
